# SillyTavern Scroll Memory

把 Mufy 的“注入式侧边记忆栏”迁移为 SillyTavern 第三方扩展。

当前版本：`v0.2.2`

## 核心机制

- 支持三种记忆生成方式：
  - **独立 API（直接填写，推荐）**：在插件内填写 OpenAI 兼容地址、密钥和模型；正文模型只负责角色扮演，回复完成后由另一条请求整理记忆。
  - **酒馆连接配置（高级）**：复用已有的 Connection Profile。
  - **正文模型兼容模式**：沿用旧版机制，由正文模型在回复末尾输出记忆标签。
- 历史记忆由扩展保存并隐藏注入；独立 API 模式不会把记忆总结任务塞给正文模型。
- 总结指令由扩展自带，不需要写入预设、世界书或角色卡；齿轮页可以手动修改并随时恢复 Mufy 默认规则。
- 短期记忆上限为 20 条；满 20 条后，下一轮要求 AI 归档成一卷长期记忆。
- 数据保存在当前 SillyTavern 聊天的 metadata 中，聊天之间互不串档。
- 重说、编辑、删除消息后，会以当前聊天的有效消息重新构建记忆，避免旧分支残留。
- 侧栏支持查看、编辑、删除、导入、导出和从当前聊天重建。

## 安装

### 方法一：通过 SillyTavern 安装扩展

打开 SillyTavern 的“扩展”页面，选择“安装扩展”，粘贴：

```text
https://github.com/1194555879-cmd/SillyTavern-ScrollMemory
```

### 方法二：手动安装

把仓库内容放到：

```text
SillyTavern/public/scripts/extensions/third-party/SillyTavern-ScrollMemory/
```

确认该目录内直接包含：

```text
manifest.json
index.js
style.css
```

重启或彻底刷新 SillyTavern。右下角出现 `📜` 即代表加载成功。

## 第一次测试

不要先动唯一原档。

1. 新建测试卡或复制一份聊天。
2. 如使用独立 API，先按下方步骤填写并测试记忆连接。
3. 正常跑 25 轮。
4. 前 20 轮确认短期记忆从 `1/20` 增长到 `20/20`。
5. 第 21 轮确认生成第一卷长期记忆，短期队列从新一轮重新开始。
6. 测试一次重说、编辑和删除，确认侧栏会按当前聊天重建。

## 独立记忆 API

默认支持直接填写 **OpenAI 兼容格式** 的连接，不需要先去酒馆创建 Connection Profile。

1. 打开卷轴记忆面板，点击右上角齿轮。
2. 工作模式选择“独立 API（直接填写）”。
3. 填写 API 地址，例如 `https://example.com/v1`。
4. 填写 API 密钥和模型名称。
5. 点击“保存设置”，再点击“测试连接”。也可以直接点“测试连接”，插件会先保存再测试。
6. 状态显示“独立 API 已就绪”后，正常发送下一轮消息。

API 密钥会写入 SillyTavern 自带的 Secrets 存储；扩展设置只保存不可反查原文的密钥编号。密钥不会出现在聊天记录、记忆导出文件或扩展设置 JSON 中。保存专用密钥后，插件还会恢复正文连接原本激活的 Custom API 密钥，避免干扰主聊天。

如果已经在使用酒馆的 **Connection Profiles / API 连接配置**，可以把工作模式切到“酒馆连接配置（高级）”继续复用。

## 记忆总结要求

齿轮页中的“记忆总结要求”会同时用于独立 API、酒馆连接配置和正文模型兼容模式。

- 不修改时，默认使用原 Mufy 规则：每轮一条高度概括的短期记忆，合并连续或有因果关系的动作，删除流水账；长期归档完整覆盖 20 条短期记忆，并保留关系变化、承诺、冲突、关键物品、地点、伏笔、长期目标和称呼变化。
- 可以在文本框中手动修改“记什么、如何概括”，点击“保存设置”生效。
- 点击“恢复默认”会立即恢复原 Mufy 规则。
- `【记忆条目】`、`【长期记忆条目】`等边界标签以及第 21 轮归档触发由插件固定管理，不会因手动修改总结要求而丢失。

独立模式每轮会产生两次互不混用上下文的请求：

- 正文请求：只负责角色扮演。
- 记忆请求：只读取本轮对话并生成记忆。

即使两套连接使用同一个服务商或同一枚 API key，它们仍然是两次独立推理，不会让正文模型在同一次生成里分心。若希望分开额度、速度或模型，也可以为记忆配置另一枚 key 或更便宜的模型。

## AI 输出格式

正文模型兼容模式会在后台要求正文 AI 把新增记忆放在以下标签中；独立 API 模式则由记忆连接生成相同格式，标签不会出现在正文聊天里：

```text
【记忆条目】
本轮新增剧情事实
【记忆完】
```

归档时还会要求：

```text
【长期记忆条目】
二十条短期记忆的压缩结果
【长期记忆完】
```

这些区块会保留在聊天数据中用于恢复，但在当前聊天界面隐藏。

## 当前状态

`v0.2.2` 新增可编辑记忆总结要求：

- 齿轮页新增大文本框，可手动调整短期记忆与长期归档的总结标准。
- 默认恢复原 Mufy 规则，明确“一轮一条、高度概括、合并连续动作、禁止流水账”。
- 提供“恢复默认”按钮；不改即使用默认规则。
- 输出边界标签与第 21 轮归档协议继续由插件固定保护。

`v0.2.1` 简化独立 API 配置：

- 齿轮页可直接填写 API 地址、API 密钥和模型名称，不再要求先创建 Connection Profile。
- 支持 OpenAI 兼容接口；末尾误填 `/chat/completions` 时会自动规范为基础地址。
- 密钥由 SillyTavern Secrets 安全保存，插件只记录专用密钥编号。
- 保存专用密钥不会替换正文模型当前使用的 Custom API 密钥。
- 原“酒馆连接配置”保留为高级模式；从 v0.2.0 升级且尚未选择配置时，会自动切换到新的直接填写页面。

`v0.2.0` 新增独立记忆 API：

- 可从酒馆现有的 API 连接配置中选择一条专用连接，不在扩展里重复保存密钥。
- 正文模型只接收历史记忆，不再承担记忆总结和长期归档任务。
- 回复完成后自动调用独立模型；短期满 20 条时由独立模型同时生成长期卷和本轮短期记忆。
- 面板右上角新增齿轮设置、连接测试以及“重试本轮”按钮。
- 默认仍保留正文模型兼容模式，更新后不会擅自改变已有聊天的工作方式。

`v0.1.6` 修复记忆内容显示 `<br>` 字样的问题：

- 新生成的多条事实改用真实换行，并明确禁止 AI 输出 HTML 换行标签。
- 捕获、导入、重建和手动保存时都会把 `<br>`、`<br/>`、`<br />` 自动转换为真实换行。
- 更新后会自动迁移当前聊天中已经保存的旧记忆，不需要手动删除或重新生成。

同时保留 `v0.1.5` 对移动端悬浮球遮挡发送器的修复：

- 悬浮球支持手指或鼠标拖动；拖动结束后不会误触打开面板。
- 位置会按屏幕比例保存在当前设备，刷新、重启和横竖屏切换后仍会恢复。
- 悬浮球始终被限制在可见屏幕内，手机端首次加载时的默认位置也已上移。

同时保留 `v0.1.4` 对“面板正常但始终为 0/20”的链路修复：

- 改用酒馆官方枚举，在每次生成前把隐藏指令重新登记到最新 user 层，贴近 Mufy 的原始注入位置。
- 同时读取酒馆保存后的聊天文本与未经美化正则处理的流式生成原文。
- 捕获结果另存到当前消息的扩展字段，避免美化正则吞掉标签后无法恢复。
- 面板新增“注入”和“捕获”状态，可直接区分插件未注入、AI 未输出标签与捕获成功。

更新后先只发一轮测试消息。正常情况应显示：

```text
注入：已装载 · user 层
捕获：成功 · 生成原文（或聊天文本）· 短期 1 / 长期 0
```

如果显示“AI 回复里没有完整记忆标签”，说明插件已经完成注入，但当前模型或更高优先级的角色格式没有遵循输出协议；把这两行状态截图用于继续排查即可，不需要改预设或世界书。

“批量补建旧聊天”将在核心 25 轮测试通过后加入，避免第一版直接对长原档做高风险操作。
